# จดเงิน — รายรับรายจ่าย + AI

รุ่นเขียนใหม่ของ `porbboyza-afk/budget-app` จดรายรับ–รายจ่ายและใช้ AI ช่วยเตรียมรายการ

## เปิดใช้งาน

เริ่มดูขอบเขตโมดูลและงานที่ยังต้องทำสำหรับ Android ใน [ARCHITECTURE.md](ARCHITECTURE.md) แนวทางผู้ร่วมพัฒนาอยู่ใน [AGENTS.md](AGENTS.md)

ใช้ Node.js 20 ขึ้นไป รัน `npm run dev` แล้วเปิด http://127.0.0.1:8771 อย่าใช้ Python static server สำหรับรุ่น AI เพราะไม่มี API ฝั่งเซิร์ฟเวอร์

คัดลอก `.env.example` เป็น `.env.local` และตั้ง `DEEPSEEK_API_KEY` หรือ `DEEPSEEK_ENV_FILE` ชี้ไฟล์ env เดิม เซิร์ฟเวอร์อ่านเฉพาะ DeepSeek key จากไฟล์นั้น ไม่ใส่ key ใน browser หรือ Git

ไม่มี dependencies สำหรับ build; ต้องเปิดผ่าน HTTP เพื่อโหลด JavaScript modules

เครื่องมือพัฒนาใช้ `npm ci` แล้วตรวจด้วย `npm test`, `npm run format:check` และ `npm run build` ใช้ `npm run format` จัดรูปแบบด้วย Prettier รุ่นที่ล็อกไว้ ไม่มีการเรียก AI หรือแตะข้อมูลจริงใน automated tests

รายงานตรวจฟังก์ชันล่าสุดอยู่ใน [FUNCTIONAL_AUDIT.md](FUNCTIONAL_AUDIT.md) การตรวจหน้าจอแบบข้อมูลจำลองใช้ `python tests/browser_audit.py` และ `python tests/pwa_browser_audit.py` หลัง build ต้องมี Python Playwright และ Brave; สคริปต์ใช้บริบทเบราว์เซอร์ใหม่ ไม่เปิดโปรไฟล์ส่วนตัว

## ลองได้ในดราฟนี้

- การเปิดใหม่เริ่มรายการว่าง ตามที่ผู้ใช้เลือกเริ่มใหม่ ข้อมูลที่จดในดราฟนี้แล้วคงอยู่
- เพิ่ม แก้ไข ลบ และย้อนกลับการลบล่าสุดระหว่างเปิดหน้า
- จดด้วยจำนวนเงินก่อน เลือกหมวดด้วยปุ่มลัด และเห็นรายการล่าสุดพร้อมแก้ไข/ย้อนกลับการบันทึก (รวมชุด AI) ระหว่างเปิดหน้า
- ทริปมีชื่อ วันเดินทาง และงบที่เว้นได้ ผูกกับรายการเดิมเพื่อดูใช้ไป/เหลือ/เกินงบข้ามเดือน โดยไม่บันทึกซ้ำ จบทริปได้โดยเก็บรายการไว้ และเปิดใหม่ได้
- รายชื่อทริปแบ่งหน้าละ 6 ทริป รายการในทริปแบ่งหน้าละ 10; หน้ารายการปกติกรองทริปได้
- ภาพรวมแสดงรายจ่ายหลัก 3 หมวดและผลต่างรายจ่ายที่จดเทียบเดือนก่อน คำนวณในเครื่องโดยไม่เรียก AI
- เลือกเดือน/ปี ค้นหา กรองประเภท และสรุปรายเดือน
- รายการแบ่งหน้าละ 10 รายการ ค้นหา/กรองก่อนแบ่งหน้า ยอดสรุปและ CSV ใช้ข้อมูลครบทั้งเดือน บันทึกหรือเปลี่ยนตัวกรองกลับหน้าแรก
- เก็บข้อมูลแยกใน browser storage; สำรอง JSON และกู้คืนแทนชุดปัจจุบันหลังยืนยัน
- ส่งออก CSV ของเดือนที่เลือก
- เงินคงเหลือคือยอดทั้งหมดถึงสิ้นเดือนที่เลือก รายรับ/รายจ่ายคือเฉพาะเดือนนั้น

## ขอบเขต

เมื่อเข้าสู่ระบบบัญชีเจ้าของ รายการจะซิงค์ D1 และมีสำรองใน browser แยกตาม UID ก่อน login ใช้ชุดข้อมูลในเครื่องแยกต่างหาก ไม่มีการย้ายข้อมูลแอปเก่า ต้องสำรองก่อนล้าง browser data; undo หายหลัง reload ไม่มีการแก้ฐานข้อมูลแอปเดิม

## PWA

เปิดเว็บออนไลน์ครั้งแรกเพื่อเตรียมไฟล์ออฟไลน์ จากนั้นติดตั้งผ่านปุ่ม «ติดตั้งจดเงิน» เมื่อเบราว์เซอร์รองรับ หรือเมนูติดตั้งของ Brave/Chrome บน iPhone ใช้แชร์ → เพิ่มไปยังหน้าจอโฮม

จดและดูข้อมูลที่มีในเครื่องแบบออฟไลน์ได้ ใช้ชุดบัญชีล่าสุดที่เคยเข้าสู่ระบบบนเครื่องนี้; บัญชีที่ยังไม่เคยซิงค์ไม่มีข้อมูลคลาวด์ให้อ่านออฟไลน์ AI, เข้าสู่ระบบ และซิงค์ต้องมีอินเทอร์เน็ต หากเปิดแบบออฟไลน์ ให้กด «เชื่อมต่ออีกครั้ง» เมื่อกลับออนไลน์

Service worker เก็บเฉพาะไฟล์หน้าจอสาธารณะ ไม่เก็บ API, token, ใบเสร็จ หรือข้อมูลบัญชีใน Cache Storage ปุ่มอัปเดตให้ผู้ใช้บันทึกงานก่อนโหลดรุ่นใหม่ Build สร้างชื่อ cache จาก SHA-256 ของ public assets อัตโนมัติ เพื่อให้ไฟล์หน้าจออัปเดตพร้อมกัน ข้อมูล browser storage ยังต้องสำรองเองและอาจถูกระบบล้างได้

## AI

- ข้อความ/ใบเสร็จ/สลิป → รายการที่แก้ไขได้ → ผู้ใช้ยืนยันก่อนบันทึก ต้องออกจากข้อมูลตัวอย่างก่อนใช้
- ส่งภาพเมื่อกดอ่านเท่านั้น ย่อด้านยาวไม่เกิน 2400px และแปลงใหม่เพื่อตัด metadata; ไม่เก็บภาพที่เซิร์ฟเวอร์ แต่ภาพถูกส่งไป DeepSeek
- สลิปที่ไม่มีวัตถุประสงค์ต้องให้ผู้ใช้เติม ห้ามถือว่ารู้ว่าซื้ออะไรจากชื่อผู้รับ
- คำถามใช้รายการเดือนที่เลือกและเดือนก่อนรวมไม่เกิน 500 รายการ โดยไม่รวม ID; ยอดคำนวณด้วยโค้ดฝั่งเซิร์ฟเวอร์ ปุ่มช่วยดูรายจ่ายที่เพิ่มเตรียมคำถามให้ แต่เรียกบริการเมื่อผู้ใช้กดส่ง
- API key อยู่เซิร์ฟเวอร์เท่านั้น; คำตอบ AI แสดงเป็นข้อความและตรวจ schema

## Cloudflare Pages

`npm run build` สร้างเฉพาะ public assets ใน `dist` และปฏิเสธไฟล์แปลกปลอมที่ตกค้าง ตั้ง Build command เป็น `npm run build`, Output directory เป็น `dist` และเปิด Pages Functions

ตั้ง server secrets/config: `DEEPSEEK_API_KEY`, `FIREBASE_WEB_API_KEY`, `FIREBASE_PROJECT_ID`, `FIREBASE_AUTH_DOMAIN`, `BUDGET_ALLOWED_EMAILS` โดยใช้ Firebase โครงการ Budget เดิม

สร้าง D1 database รัน `schema.sql` และผูกชื่อ `BUDGET_AI_DB` endpoint จะปฏิเสธหากไม่มีบัญชีเจ้าของหรือ quota binding จำกัด 5 ครั้ง/นาที, 60 ครั้ง/บัญชี/วัน และ 100 ครั้งรวม/วัน (UTC) รวมคำขอที่ provider ล้มเหลว ไม่ใช่การรับประกันยอดเงินค่า API เป๊ะ

Google sign-in ต้องเปิด provider และอนุญาต domain ใน Firebase ก่อนใช้งานจริง อ่าน `RELEASE_HANDOFF.md` ก่อน merge/deploy ผู้ใช้เลือกเริ่มใหม่โดยไม่ย้ายข้อมูลเก่า ห้ามคัดลอก `.env*`, `.dev.vars*` หรือข้อมูลจริงเข้า Git

การตรวจ: independent source review และ synthetic CAS checks ผ่าน; Brave Google login, เพิ่ม/แก้/ลบ/ย้อนกลับและซิงค์ขึ้น D1, รีเฟรชคงข้อมูล, DeepSeek ข้อความและถามยอดผ่านจริง ภาพใบเสร็จ/สลิปไทยสังเคราะห์ผ่าน แต่ยังไม่ได้ประเมินกับภาพจริงหลากหลายรูปแบบ

เว็บใช้งาน: https://budget-app-porbboyza.pages.dev ลิงก์ GitHub Pages เดิมส่งต่อมาที่เว็บนี้

## โครงสร้าง

เมนู ภาพรวม · จด · รายการ · ทริป · ข้อมูล สลับหน้าจอภายในแอป แสดงเฉพาะหน้าที่เลือก ไม่เลื่อนผ่านทุกส่วน มือถือใช้เมนูด้านบนแบบติดตำแหน่ง รองรับปุ่มย้อนกลับและลิงก์ตรง เช่น `/#transactions` การสลับเมนูเก็บช่องกรอกและตัวกรองไว้ รายการยังแบ่งหน้าละ 10 บัญชีแยกอยู่มุมบน หลังล็อกอินเป็นรูปวงกลมและจุดสีเขียว (หมายถึงเข้าสู่ระบบ ไม่ได้ยืนยันซิงค์สำเร็จ) กดเพื่อดูบัญชีและออกจากระบบ

`model.js` ตรวจ schema และยอดสตางค์; `ledger-domain.js` รวมกฎค้นหา/แบ่งหน้า/AI/undo ที่ไม่ผูกกับเบราว์เซอร์; `ledger-repository.js` รวมการเก็บข้อมูลและค่าทริปตามบัญชีผ่าน adapter; `app.js` เชื่อมหน้าจอ; `trips.js` และ `ai-ui.js` แยกส่วนทริปและ AI; `ui-format.js` รวมรูปแบบแสดงผล; `styles.css` และ `index.html` เป็นหน้าตาเว็บ

ข้อมูลรุ่น 2 อ่านไฟล์รุ่น 1 ได้และเก็บต้นฉบับในเครื่องก่อนการเขียนครั้งแรก เซิร์ฟเวอร์ปฏิเสธการซิงค์จากแอปรุ่นเก่าเพื่อป้องกันทริปหาย หากเปิดหลายแท็บให้อัปเดตทุกแท็บ สำรอง JSON รวมทั้งรายการและทริป; CSV เพิ่มคอลัมน์ชื่อทริป
